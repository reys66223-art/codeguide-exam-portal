# codeguide-exam-portal App Flow Document

## Onboarding and Sign-In/Sign-Up

When a new user arrives at the exam portal, they first land on a simple introduction page that explains the purpose of the platform and offers two clear entry points. Teachers are prompted to sign up or sign in using their email and a secure password or through an OAuth method such as Google. Students see a separate link inviting them to enter a unique exam code along with their name and, if required, date of birth. For teachers who choose email sign-up, they complete a form that captures their name, email address, and desired password, then click a confirmation link sent by email. If a teacher forgets their password, they can click a “Forgot Password” link, submit their email address, and receive a reset link to set a new password. For teachers using social login, clicking the Google button opens a pop-up for Google authentication and returns them to the dashboard once approved. Students skip traditional sign-up and land on a code entry page where they type the exam code and personal details. The system verifies these details through an API call, and upon success, it creates a temporary session for the student and redirects them to their exam interface.

## Main Dashboard or Home Page

After logging in, a teacher arrives on the main dashboard page. At the top, a header shows the platform name alongside a theme toggle for light and dark mode and their profile avatar. Along the left side, a vertical navigation menu lists links for Exams, Questions, Monitoring, and Account Settings. The center of the page features quick-access cards that display the number of active exams, upcoming test schedules, and recent student activity. From this view, the teacher can click on the Exams link to see a table of all existing exams or click the Monitoring link to jump straight to live session tracking. Below the cards, there is a feed of notifications about exam results or AI grading completions. Students have a different home page. After entering the exam code, they arrive on a clean interface that shows the exam title, a countdown timer at the top, and a question panel below. The header also shows a progress bar indicating how many questions are left and a logout button in case they need to leave early.

## Detailed Feature Flows and Page Transitions

When a teacher selects the Exams link, they land on the Exam Management page. This page lists each exam’s name, duration, and unique code. Clicking a button labeled “Create New Exam” opens a full-page form where the teacher enters the exam title, duration in minutes, and optionally sets the date and time. After saving, they are redirected to the exam detail page, which has tabs for Questions, Student Sessions, and Settings. In the Questions tab, the teacher clicks an Add Question button to open a modal form where they choose between multiple-choice or essay type. For multiple-choice, fields appear for question text, four answer options, and the correct answer. For essays, a text area appears for the prompt and another area for the model answer. Saving returns them to the question list. In the Student Sessions tab, the teacher sees live data for each student who has joined the exam code. They can refresh or toggle real-time updates. The Settings tab lets the teacher regenerate the exam code or adjust time allowances.

When a student begins an exam, they arrive on the exam interface page. At the top, the timer starts counting down from the allotted duration. Below, the first question appears with radio buttons for multiple-choice or a rich-text area for essay responses. As soon as they begin typing or selecting, an auto-save function fires every thirty seconds, sending the current answer to the server. Navigating to the next or previous question updates the progress bar and scrolls the view to the next item. If the student reaches an essay question, once they move on or click Save, the system sends their response to a background API route for AI grading. This route calls the Gemini AI service and receives a score, which is stored and will be displayed on the final results page. When the timer reaches zero or the student clicks a Submit Exam button, a confirmation dialog appears. Confirming ends the session, stops the timer, and redirects the student to a results summary page showing their total score and a breakdown by question type.

## Settings and Account Management

Teachers access account settings by clicking their profile avatar in the header and selecting Account Settings. This page shows their name, email, and password change form. It also includes options for updating notification preferences, such as receiving an email when an essay has been graded by the AI. Any changes made here are saved with a click of the Save button and a confirmation banner appears. Students have a minimal settings page accessible via a small gear icon on the exam interface. They can update their name if they mistyped it before starting, and they can view the exam code in case they need to share it with an invigilator. Both teacher and student can always return to their main dashboard or exam interface by using the navigation menu or the Home link in the header.

## Error States and Alternate Paths

If a teacher enters an invalid email or password on sign-in, an inline error appears beneath the form field explaining that the credentials are incorrect. If the OAuth pop-up fails, a banner at the top informs them that the social login could not be completed and invites them to try again. Students who enter an invalid or expired exam code see a message indicating the code was not found and prompting them to double-check with their teacher. During the exam, if the auto-save fails due to network loss, a small red indicator appears next to the timer and the system retries saving every ten seconds until connectivity is restored. If the AI grading service is unavailable, the student’s essay question is marked pending, and the teacher sees an alert in the Monitoring view. Any critical API errors redirect the user to a friendly fallback page explaining that something went wrong, and it provides a button to retry or contact support.

## Conclusion and Overall App Journey

A teacher begins by signing up with email or social login, sets up their profile, and then creates new exams and questions through a guided form-based interface. They publish an exam code and monitor student activity in real time. A student uses the exam code to join and experiences a streamlined exam interface with auto-save and a countdown timer. Essay answers are graded automatically using the Gemini AI integration, and all results are compiled on a final summary page. Both teachers and students can adjust their account settings, recover from network interruptions, and follow clear error messages if something goes wrong. This end-to-end flow ensures that teachers can create and manage exams easily while students enjoy a reliable and responsive testing experience.
